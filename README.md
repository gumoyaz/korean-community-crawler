# 커트 — 커뮤니티 트렌드

한국 주요 인터넷 커뮤니티의 인기글을 10분마다 모아 **지금 화제인 글들을 한눈에** 보여주는 사이트입니다.
매일 KST 12시 이후에는 Gemini가 그날의 화제를 정리한 **데일리 리포트**를 만듭니다.

- 사이트: https://gumoyaz.github.io/korean-community-crawler/
- 비용: 0원 (GitHub Actions + GitHub Pages, 상시 서버 없음)

## 동작 방식

```
cron-job.org (10분마다) ──▶ GitHub Actions: Build and deploy
schedule (백업, :07/:22/:37/:52)      │
                                     ├─ 1. 직전 상태 복원 (Actions 캐시 → 없으면 사이트의 data/state.json), audio 브랜치의 음성 파일 받기
                                     ├─ 2. 크롤링 1회 (todaybeststory API, 빠지거나 멈춘 커뮤니티만 직접 스크래핑·이슈링크로 채움) → 지금 뜨는 이슈 묶기
                                     ├─ 3. 메인 AI 요약 (6시간마다) / 데일리 리포트 (정오본·최종본)
                                     ├─ 4. 데일리 음성 (Gemini TTS, 데일리 생성을 시도하지 않은 실행에서 최대 1개)
                                     ├─ 5. _site/ 에 정적 사이트 렌더링 (build.py)
                                     ├─ 6. 새 데일리 리포트가 있으면 data/daily/*.json 을 main 에 커밋, 음성이 바뀌었으면 audio 브랜치 교체
                                     ├─ 7. GitHub Pages 에 배포
                                     └─ 8. 수집 이상이 3번 연속이면 source-health 이슈 열기, 풀리면 닫기 (health 잡)
```

- 사이트 자체는 정적 파일이라, 크롤이 실패해도 마지막으로 배포된 화면이 그대로 떠 있습니다.
- 데일리 리포트는 리포에 JSON으로 커밋되므로 호스팅을 옮겨도 사라지지 않습니다.
- 브라우저는 `data/trends.json`을 10분마다 다시 읽습니다. 서버 API는 없습니다.

## 수집 소스

### todaybeststory.com API (주 경로)

21개 커뮤니티의 당일 인기글 전체(보통 하루 1,300~2,000건)를 끝 페이지까지 받습니다.
FM코리아, 디시인사이드, 아카라이브, 네이트판, 보배드림, 웃긴대학, 딴지일보, 루리웹, 클리앙, 더쿠, MLB파크,
인스티즈, 개드립, 이토랜드, 가생이, 인벤, 뽐뿌, SLR클럽, 오늘의유머, 와이고수, 82쿡.

- 조회 날짜는 KST 기준이고, KST 00~02시에는 전날 목록도 함께 받습니다.
- 페이지 크기는 실행마다 `limit=100`과 `99`를 번갈아 씁니다. API 응답이 URL별로 약 10분 캐시돼서, 같은 URL을 쓰면 직전 실행의 캐시를 다시 읽게 됩니다.
- FM코리아 조회수는 API가 주는 합성값이라 0으로 둡니다(소스 간 비교 왜곡 방지). 이슈링크로 받은 FM코리아 글도 0으로 둡니다.
- 일베는 2024-08 이후 API에 글이 없어 뺐습니다.

### 커뮤니티별 수집 상태 (`source_health`)

API 응답에서 커뮤니티마다 마지막 갱신 시각(`updateDatetime` 최댓값)·마지막 새 글 시각·글 수를 모아 상태를 매깁니다.

| 상태 | 뜻 |
|---|---|
| `ok` | 정상 |
| `degraded` | 글은 있는데 90분 넘게 갱신이 없음 (KST 06~24시에만 판정) |
| `missing` | 그 시각이면 당일 글이 있어야 하는데 없음. 커뮤니티마다 기대 시각이 다름(`crawler.EXPECTED_BY_HOUR`, 09-22~25 첫 수집 시각 + 여유 — 인스티즈·와이고수는 10시). 하루 글이 1~14건뿐인 오유·가생이·인벤은 판정하지 않음 |
| `blocked` | API에서 빠졌거나 멈췄는데 직접 스크래핑도 막혔고(4xx·챌린지 페이지 등) 이슈링크로도 못 채움 |

전체 `status`는 넷 중 하나입니다.

- `ok` — 정상.
- `partial` — API 목록이 중간에 끊겼거나 장애였거나, 빠지거나 멈춘 커뮤니티가 3곳 이상. 예비 경로로 채우고, 이번에 빠진 커뮤니티는 이전 글을 유지해 병합합니다(`kept`).
- `stale` — API가 온전하지 않은데 예비 경로까지 합쳐도 6곳·150건에 못 미쳐 이전 목록을 그대로 둠.
- `stale-source` — 응답은 오는데 API 전체의 마지막 갱신이 90분 넘게 과거 (`degraded`처럼 KST 06~24시에만 판정).

### 이슈링크 (2차 소스, `sources_issuelink.py`)

[이슈링크](https://www.issuelink.co.kr)의 커뮤니티별 인기순 목록(15곳)에서 글을 받아 `via: 'issuelink'`로 표시합니다. 원본 링크는 이슈링크 이동 주소(`/community/go/…`)의 `Location` 헤더로 풀고, 풀린 주소는 `state.json`에 캐시해 같은 글을 다시 묻지 않습니다.

- **(a)** API에서 `degraded`·`missing`이거나 API 목록이 온전하지 않은 커뮤니티를 채웁니다.
- **(b)** 당일 API 글이 5건 미만인 커뮤니티(오유 등)를 보탭니다. KST 02~12시 오전 보충 중에는 어제 글이 넉넉했던 커뮤니티(새벽이라 아직 API 목록이 작을 뿐인 곳)는 빼고 그 칸을 전날 인기글로 채웁니다 — 이때 (b)는 어제도 글이 적었던 오유·인벤·웃대 정도입니다. (b)는 (a)가 같이 있어도 30분에 한 번만 새로 받고 그 사이에는 직전 글을 다시 씁니다.
- 공식 베스트가 아니라 이슈링크 자체의 인기순이고 약 15~25분 늦습니다. 같은 글이 API와 이슈링크에 다 있으면 API 쪽을 쓰고, 갱신이 멈춘 커뮤니티에서만 이슈링크 쪽(새 수치)을 씁니다. SLR·보배드림은 베스트 게시판 글 번호가 따로 매겨져 같은 글도 주소가 달라서, 다른 경로에서 온 같은 커뮤니티·같은 제목 글도 같은 글로 봅니다.
- robots.txt를 확인하고(5xx·연결 실패면 그 실행은 건너뜀), 동시 연결·간격·전체 20초 상한을 둡니다. 실패해도 크롤은 계속됩니다.
- **Actions 러너(미국 IP)에서는 쓸 수 없습니다.** 이슈링크가 해외 IP에 JS 봇 확인 페이지를 주기 때문입니다(2026-09-25 실측, 한국 IP에서는 정상). 이 확인은 풀지 않고, robots.txt 자리에 HTML이 오면 그 실행은 건너뜁니다.

### 직접 스크래핑 (예비 경로)

`degraded`·`missing`인 커뮤니티, 또는 API 목록이 온전하지 않을 때 25개를 못 채운 커뮤니티만 아래 17곳에서 직접 긁습니다.
오늘의유머, 루리웹(베스트), 클리앙, 더쿠, MLB파크(불펜 베스트), 보배드림, 네이트판(톡커들의 선택), 웃긴대학, 아카라이브, 딴지일보, 디시인사이드(실시간 베스트), 뽐뿌(HOT), 인벤(오픈이슈갤러리 추천), 82쿡(많이 읽은 글), 이토랜드(인기 순위), 와이고수(실시간 인기), 개드립(인기순).

- Actions 러너(미국 IP) 실측(2026-09-25): 오유·아카라이브·인스티즈·FM코리아는 막히고 MLB파크·SLR은 연결 오류입니다. 나머지는 접속됩니다.

- 행 단위로 파싱해서 제목·조회수·날짜가 항상 같은 글에서 나옵니다.
- 공지·광고·댓글 수 링크는 걸러냅니다. FM코리아·인스티즈는 봇 차단 때문에 직접 요청하지 않습니다.
- 4xx, 안내 페이지 리다이렉트(`msg.html`), 행 0개(챌린지·'보안 검사' 페이지)는 차단으로 기록합니다(`source_health.note`). 오유·더쿠·웃대는 해외 IP에서 막히는 것으로 측정됐지만, 되는 동안은 씁니다.
- 실제 Actions(해외 IP)에서 되는지는 **Source probe** 워크플로로 잽니다(아래 [소스 실측 프로브](#소스-실측-프로브-source-probe)).

### 오전 보충 (전날 인기글)

KST 00~02시 실행이 받은 전날 목록에서 커뮤니티별 상위 25개를 `state.json`에 둡니다(추가 요청 없음). 02~12시에는 당일 글이 25개에 못 미치는 커뮤니티 칸만 이 글로 채우고 `prev_day: true`('어제' 표시)를 붙입니다. 순위는 당일 글 뒤입니다. API 당일 글만으로(이슈링크·직접 수집·이전 글 유지는 세지 않음) 19곳·350건이 되면 채우지 않고, 12시가 되면 그날은 끝냅니다. 12시 전에는 저장한 전날 글을 지우지 않고 실행마다 다시 판정합니다. 전날 글은 이슈 보드, AI 요약 입력, 정오본 데일리 입력에서 뺍니다.

### 수집 이상 알림

빌드마다 커뮤니티별 상태 표를 실행 요약(Step Summary)에 남깁니다. 알림 대상 문제가 3번 연속이면 `source-health` 라벨 이슈를 열고(GitHub 알림), 상태가 바뀔 때만 코멘트하고, 풀리면 닫습니다.

- 알림 대상: `stale`·`stale-source`·`partial`, 또는 `missing`·`blocked`인 커뮤니티.
- `degraded`(API 갱신만 멈춤)는 칩 표시만 하고 알리지 않습니다. 원본 쪽 문제라 고칠 수 없고, 인스티즈는 거의 매일 몇 시간씩 멈춥니다(첫 운영 하루에 이슈 4번). 하루 넘게 멈추면 다음 날 기대 시각에 `missing`이 되어 알리고, 여러 곳이 같이 멈추면 `partial`로 알립니다.
- 이전 이슈가 닫히지 않고 남아 있어도 새 장애의 첫 알림(3번째)은 그 이슈에 코멘트합니다. 닫기는 풀린 뒤 3번의 실행에서 시도해서, 한 번 실패해도 다음 실행이 닫습니다.
- KST 00~06시에는 `degraded`·`stale-source`를 판정하지 않으므로(00~02시에는 전날 목록도 같이 봄) 이 시간의 '문제 없음'으로는 이슈를 닫지 않습니다. 자정 전부터 이어진 장애는 같은 이슈에 이어서 알리고, 이 시간에 실제로 풀렸으면 06시 이후 판정으로 닫힙니다.
- 알림은 GitHub 기본 알림(이메일·앱)으로 옵니다. 리포를 Watch하고 있어야 받습니다(자기 리포는 기본으로 Watch).

### 소스 실측 프로브 (Source probe)

실제 러너(해외 IP)에서 소스마다 요청이 되는지 재는 수동 실행 워크플로입니다(`.github/workflows/source-probe.yml`, `tools/probe_sources.py`). 크롤·state·커밋·배포는 하지 않습니다.

1. Actions 탭 → **Source probe** → Run workflow. `only`를 비우면 전부 잽니다(요청 사이 1~1.5초, 약 2~3분). 쉼표로 `tbs`, `fallback`, `issuelink`, `candidates` 중 일부만 고를 수 있습니다.
2. 결과는 그 실행의 요약(Step Summary) 표와 아티팩트 `source-probe-<실행 ID>`(JSON·MD, 30일 보관)로 남습니다. 러너의 국가·망은 ipinfo.io로 조회해 적습니다(IP는 남기지 않음).
3. 판정: `ok` / `blocked`(401·403·429·430·451·503, Cloudflare 챌린지, '보안 검사' 페이지, `msg.html` 리다이렉트) / `empty`(200인데 파서가 0행 — 선택자 고장 또는 내용 없는 차단 페이지) / `http-NNN` / `error`(연결 실패). `fallback`의 행 수는 크롤러와 같은 파서(`_parse_rows`)로 셉니다.

로컬에서는 `python tools/probe_sources.py --only tbs,issuelink --no-ipinfo`처럼 돌립니다. 표는 화면에, JSON·MD는 임시 폴더(`--out`으로 바꿈)에 남습니다. 한국 IP라 러너 결과와 다를 수 있습니다(2026-09-25 로컬 측정에서는 인스티즈 `/pt`만 403).

## 화면 구성

- **🔥 지금 뜨는 이슈** — 여러 커뮤니티에 같이 올라온 인기글을 이야기 단위로 묶은 보드입니다(묶는 방식은 아래 [지금 뜨는 이슈](#지금-뜨는-이슈) 참고).
  - 이슈 하나는 세 줄입니다: 이름과 종류·상태 배지 / 대표 글의 출처와 제목(퍼진 글은 올라온 커뮤니티들) / 커뮤니티 색 점·N곳·글 수·`+N 새 글`·댓글·시작 뒤 지난 시간(`8시간째`).
  - 기본으로 넓은 화면은 5개, 모바일은 3개를 보이고 `이슈 N개 더`로 나머지를 펼칩니다. 그 아래 `여기서만 뜨거운 글` 목록은 접혀 있고, 처음 불러올 때 이슈가 5개 미만이면 펼쳐 둡니다.
  - 이슈를 누르면 대표 글 최대 3개(원글 링크), 첫 글·최근 글 시각, 커뮤니티별 글 수(그 커뮤니티 안 3위 안이면 순위도), 함께 나온 말, 상태 근거가 나옵니다. 넓은 화면은 오른쪽 패널(고르기 전에는 1위), 모바일은 그 자리에서 하나씩 펼칩니다.
  - `이 이슈 글 N개 모두 보기`를 누르면 아래 피드가 그 이슈 글로만 걸러집니다. 카테고리 탭·커뮤니티 칩과 함께 쓸 수 있고, 그동안 탭·칩 숫자도 그 이슈 글 기준으로 바뀝니다(글이 없는 커뮤니티 칩은 숨김). 필터 막대의 ✕로 해제합니다.
  - 자동 갱신 뒤에도 펼침·선택·필터는 이슈 id로 유지됩니다. 보던 이슈가 목록에서 빠지면 보드에 알리고, 필터 중이던 이슈가 빠지면 마지막으로 본 글로 계속 거르며 필터 막대에 '목록에서 빠진 이슈'로 표시합니다.
  - 머리줄에는 갱신 상태(n분 전 갱신·수집 지연·원본 갱신 멈춤·일부 커뮤니티 수집 지연), 기준 시각(배지와 같은 데이터 갱신 시각), 커뮤니티·글 수가 나옵니다. 글이 350개 미만이면 '지금은 글이 적은 시간'을, 상태 배지가 아직 켜지지 않았으면 '변화 추이는 몇 시간 뒤부터'를 덧붙입니다.
- **✨ AI 요약** — 보드 아래에 전체 문단이 그대로 보입니다. Gemini가 커뮤니티별 대표글을 주제별로 묶은 요약입니다(6시간마다, 24시간 넘으면 숨김).
- **카테고리 탭** — 전체 / 게임·IT / 연예·아이돌 / 유머 / 음식·카페 / 뷰티·패션 / 자동차
- **커뮤니티 칩** — 사이트별 필터 (글 수 표시). 수집이 멈춘 커뮤니티는 칩에 점을 찍습니다(주황: 갱신 멈춤, 빨강: 수집 안 됨·접속 차단). 점에 마우스를 올리면 뜻이 나오고(스크린리더는 칩 이름 뒤에 한 번 읽음), 그 칩을 고르면 카드 위에 안내 한 줄이 나옵니다. '마지막 갱신 n시간 전'은 원본의 마지막 갱신 시각을 알 때만 붙입니다. 글이 0개여도 멈춘 커뮤니티의 칩은 남깁니다.
- **카드 피드** — 출처 배지, 본문 요약, 시각, 조회·추천·댓글. 클릭하면 원글로 이동. 이슈링크로 모은 글은 출처 옆에 `(이슈링크)`, 오전에 빈 칸을 채운 전날 글은 `어제` 배지
- **데일리 리포트** (`/daily/`) — 날짜별 아카이브, 이전/다음 이동, 읽어주기(아래 [읽어주기](#읽어주기) 참고)

## 데일리 리포트

| 시점 (KST) | 동작 |
|---|---|
| 12:00 이후 첫 실행 | 오늘 **정오본** 생성 |
| 다음 날 00:10~01:59 | 하루 전체 목록으로 전날 **최종본**을 다시 생성해 덮어씀 (정오본이 없으면 백필) |
| 생성 실패 | 30분 뒤 다음 실행에서 자동 재시도 |

- 입력은 그날 글 가운데 랭킹 상위 20개입니다. 한 커뮤니티는 최대 4개까지만 넣고, 커뮤니티가 10곳 미만이면 생성을 미룹니다.
- 프롬프트는 제목·본문에 있는 사실만 쓰게 합니다. 입력에 없는 소속·직함·반응은 추측하지 않습니다.
- 모델은 `gemini-3.8-flash`입니다. 실패하면 예비 모델 `gemini-3.6-flash` → `gemini-3.5-flash` → `gemini-3.5-flash-lite`를 차례로 한 번씩 시도합니다(모델마다 503이 나는 시간대가 달라서). 모두 환경변수로 바꿀 수 있습니다.
- 저장 형식은 `data/daily/YYYY-MM-DD.json`입니다. 필드는 `date, generated_at, model, post_count, analyzed_count, summary_md, posts`입니다.

### 읽어주기

데일리 상세 페이지 위쪽 플레이어가 요약을 소리 내어 읽습니다. 버튼은 ⏮ 이전 섹션 / ▶·⏸ / ■ 정지 / ⏭ 다음 섹션이고, 속도는 0.85·1·1.2·1.5×입니다. 지금 읽는 섹션의 제목을 강조합니다.

- **음성 파일 재생** — 페이지에 음성 파일 정보(`summary.audio`: 주소·길이·섹션 시작 시각)가 있으면 `<audio>`로 재생합니다.
  - 속도는 `playbackRate`로 바꾸고 음높이는 유지합니다. 진행 막대 옆에 경과·전체 시간이 나옵니다.
  - ⏮/⏭는 섹션 시작 시각으로 옮깁니다. ⏮는 지금 섹션을 3초 넘게 들었으면 그 섹션 처음으로 갑니다.
  - ▶를 누르기 전에는 파일을 받지 않습니다(`preload="none"`). 섹션 수가 본문 제목 수와 다르면 섹션 이동·강조 없이 재생만 합니다. 잠금 화면·알림의 미디어 컨트롤용 정보(Media Session)도 등록합니다(지원 브라우저만, 실기기 확인 전).
- **브라우저 음성(대체 경로)** — 음성 파일이 없거나 불러오지 못하면(404·디코드 실패·재생 중 끊김) 브라우저 음성(Web Speech)으로 읽습니다.
  - 재생 중에 실패하면 그 섹션부터 바로 이어 읽습니다. 일시정지해 둔 상태였다면 소리 없이 기다렸다가 다음 ▶ 때 그 섹션부터 읽습니다. 전환 안내는 플레이어 아래에 한 줄로 나옵니다.
  - 한국어 음성은 Edge 신경망(`Natural`·`Online`) → `Google` → Apple(`Yuna`·`Siri`·`Premium`·`Enhanced`) → 기타 → Windows 기본 `Heami` 순으로 고릅니다.
  - 한국어 음성이 둘 이상이면 음성 고르기 메뉴가 나옵니다. 고른 음성은 그 브라우저에 기억합니다(localStorage `kt.ttsVoice`).
- **음성 파일 만들기** — Actions가 리포트마다 Gemini TTS(`gemini-3.8-flash-tts`, 목소리 `Kore`)로 리포트 전체를 한 번에 합성해 MP3(48kbps, 2분에 약 0.8MB)로 만듭니다.
  - 리포트를 만든 다음 실행(약 10분 뒤)에 음성이 나옵니다. 그 전이나 실패했을 때는 브라우저 음성으로 읽습니다. 최종본으로 바뀐 리포트는 음성을 다시 만듭니다.
  - 한 실행에 최대 1개, 최근 7일 리포트까지 만듭니다. 실패하면 30분(일일 한도 소진이면 180분) 뒤에 다시 시도하고, 하루(KST) 최대 6회까지 시도합니다.
  - 만든 음성이 `audio` 브랜치에 올라가지 않으면(브랜치 규칙 등) 다음 실행이 알아채고 `state.json`의 `tts.error`에 `publish_failed`를 남깁니다. 30분 뒤 한 번 더 만들고, 또 실패하면 그날은 더 만들지 않습니다.
  - 음성 파일은 main이 아니라 `audio` 브랜치에 최근 14일치만 둡니다(매번 커밋 1개로 교체해 히스토리가 쌓이지 않음). 빌드가 받아서 사이트의 `/audio/`로 함께 배포합니다.
  - 자세한 설계(섹션 경계 찾기, 저장 방식)는 CLAUDE.md의 '데일리 음성 파일(Gemini TTS)'에 있습니다.

## 랭킹 로직

원칙: **실제로 많은 사람이 본 글이 위로**, 단 커뮤니티 크기가 달라 큰 곳으로만 몰리지 않게 **커뮤니티를 고르게** 섞는다(2026-09-26).

**1. 인기 점수 (전체 순위)** — `log10(1 + 추정 조회수 × 신선도)`

- 추정 조회수: 조회수가 있으면 그대로 씁니다. FM코리아(API 조회수가 합성값)·개드립(조회수 없음)처럼 없으면 `댓글 × 100`, 댓글도 없으면 `추천 × 100`으로 추정합니다(댓글이 많은 디시·더쿠·클리앙·SLR의 조회수/댓글 비율 91~125). 셋 다 없는 직접 수집 목록은 같은 커뮤니티의 중앙값에 목록 순서를 곱합니다.
- 신선도: 반감기 24시간. 조회수는 시간이 지날수록 쌓이므로 오래된 글이 앞서지 않게 합니다.

**2. 커뮤니티 균형** — 같은 커뮤니티의 k번째 글(0부터)은 점수에서 `0.6 × k`를 뺍니다(조회수로 약 ÷4). 09-26 데이터로 상위 25개에 18곳, 한 곳당 최대 2개가 들어가고 21곳 모두 31위 안에 나옵니다. 커뮤니티당 최대 25개입니다.

**3. 커뮤니티 안 점수 (`rank_score`)** — 이슈 보드 급상승 판정과 데일리 리포트 선정은 이 점수를 씁니다(소스 간 원시 조회수를 비교하지 않음). 소스 안에서 로그 정규화한 뒤 가중 합산합니다.

```
engagement = 조회수×0.60 + 추천수×0.25 + 댓글수×0.15
base       = 위치점수×0.35 + engagement×0.65      (조회수가 없는 소스는 위치 점수만)
```

전날 글 보충('어제')은 당일 글 뒤에 붙습니다. 원본 목록이 직전과 같으면 순위도 그대로 둡니다.

## 지금 뜨는 이슈

`issues.py`가 빌드마다 랭킹된 글을 이야기(이슈) 단위로 묶습니다. 제목만 보고 규칙으로 묶으며 LLM·형태소 분석기·새 의존성은 쓰지 않습니다. 실데이터(글 300~700개)에서 0.1~0.4초 걸립니다.

**묶는 방식**

1. 할인·포인트 적립 글은 묶기에서 뺍니다(피드에는 그대로 나옵니다). 기사식 한자 약칭은 묶기용 사본에서만 이름으로 풉니다(`李 대통령` → `이재명 대통령`).
2. 제목을 규칙 토크나이저로 자릅니다. 말머리·확장자·자모를 떼고 조사·어미를 없앤 뒤 별칭을 통일합니다(`PUBG`·`펍지` → `배그`). 숫자+단위(`7개월`·`40대`)도 단어로 쓰고, 합성어는 두 조각이 각각 2글 이상에 나올 때 쪼갭니다(`삼성냉장고` → `삼성`·`냉장고`).
3. 글마다 대표 구체어(home) 하나를 고르고, 같은 home을 가진 글끼리 잇습니다. `한국`·`대통령`·`선수` 같은 일반어(`GENERIC`)와 `사태`·`논란` 같은 사건어(`LINK_STOP`)는 잇는 근거로 쓰지 않습니다.
4. 두 home이 같은 글에 자주 함께 나오면 합칩니다(함께 나온 글 2개 이상, 작은 쪽의 30% 이상).
5. 제목 글자 2-gram Jaccard가 0.45 이상이면 같은 글을 퍼나른 것으로 보고 잇습니다.
6. 외톨이 글과 한 커뮤니티 안의 묶음은 한 번만 붙이고 사슬처럼 잇지 않습니다. 글 15개나 커뮤니티 8곳을 넘는데 가장 흔한 단어가 글의 절반을 못 덮는 묶음은 합치기 전 상태로 되돌립니다.

**보드에 싣는 조건** — 2곳 이상의 커뮤니티에 걸친 묶음만 싣고, 다음 중 하나를 만족해야 합니다: 글 4개 이상 / 퍼나르기 묶음 / 단어 2개 이상(하나는 일반어가 아닌 것)을 같이 쓴 글 쌍이 있음. 퍼진 글이 아니면 일반어가 아닌 핵심어가 있어야 합니다. 최대 8개까지 싣습니다.

**종류**

| 종류 | 화면 표시 | 뜻 |
|---|---|---|
| `repost` | 퍼진 글 | 같은 글이 여러 곳에 올라옴(퍼나르기로만 이어진 묶음) |
| `topic` | 주제 | 한 인물·주제 아래 여러 이야기가 섞임(글 5개 이상, 핵심어 하나가 60% 이상을 덮음) |
| `story` | (배지 없음) | 그 밖의 이슈 |

이슈 이름은 묶음 안 2글 이상에 나온 인접 명사 구절(최대 4단어)로 짓고, 구절이 없으면 핵심어 두 개를 씁니다. 2글 이상에 공통으로 나온 사건 명사(`사고`·`논란`·`폭발` 등)가 있으면 끝에 붙입니다. 주제는 핵심어 하나로(직함 같은 일반어가 붙은 구절은 허용: `이재명 대통령`), 퍼진 글은 대표 글 제목(30자까지)으로 이름을 붙입니다.

**순서**

```
spread = Σ(커뮤니티별 최고 rank_score) / 100 + Σ 0.5 × ln(그 커뮤니티의 글 수)
heat   = spread × (0.7 + 0.6 × 신선도)
```

- 신선도는 최근 2라운드에 처음 보인 글의 비율입니다. 점수 이력이 3라운드 미만이면 0.5로 둡니다.
- 한 커뮤니티에 여러 번 올라온 글은 로그로만 더해서, 서로 다른 커뮤니티로 퍼질수록 위로 갑니다.
- 퍼진 글은 신선도 없이 `spread × 0.8`로, 주제는 `× 0.75`, 잠잠은 `× 0.8`로 계산합니다(밈이나 매일 있는 배경 주제가 실제 사건 위로 오르지 않게).

**상태**

| 상태 | 조건 |
|---|---|
| 신규 | 두 번째로 이른 글이 최근 3시간 안 (첫 글 하나가 엉뚱하게 오래된 경우를 피하려고 두 번째 글 기준) |
| 급상승 | 3번 전 갱신보다 글이 3개 이상(2개라도 1.5배가 되면) 늘었거나 커뮤니티가 2곳 이상 늘었을 때(점수 이력 4라운드 이상). 또는 최근 3시간 안에 쓴 글이 2개 이상이면서 전체의 1/4 이상일 때 |
| 잠잠 | 마지막 글이 8시간 넘게 지남 (작성 시각이 있는 글 2개 이상) |
| 지속 | 그 밖 |

- 점수 이력(`post_score_history`)은 API 목록을 끝까지 받은 라운드만 넣고, 40분 안에 온 라운드는 한 칸으로 묶어(칸 하나 ≈ 원본 갱신 한 번, 약 1시간) 최근 4시간·6칸까지 둡니다. 목록이 직전과 같으면 넣지 않습니다. 이 이력이 3라운드 이상일 때만 상태 배지와 `+N 새 글`을 보여 줍니다. `+N`은 직전 라운드에 없던 글 수입니다.
- **여기서만 뜨거운 글**은 보드 이슈에 들지 않은 글 가운데 커뮤니티 안 1~2위 글에서 고릅니다. 커뮤니티 안 댓글 백분위가 높은 글과 1위 글을 앞에 두고, 커뮤니티당 1개씩 최대 6개입니다.
- 선정적인 제목이나 욕설이 든 제목은 대표 글 순서에서 뒤로 밀고 둘째 대표 글부터는 빼며, 여기서만 뜨거운 글에는 올리지 않습니다(피드에는 그대로 나옵니다).
- 이슈 id는 가장 먼저 보인 글의 URL로 만들어서 갱신 사이에도 펼침·필터가 유지됩니다. 동점이면 묶음 안에서 먼저 나온 것을 고르므로 같은 입력이면 실행마다 결과가 같습니다.
- 이슈 계산이 실패해도 빌드는 계속되고 빈 블록(`items: []`)이 나갑니다.
- **튜닝 로그**: 결과가 바뀐 빌드의 요약 `{t, posts, communities, items: [{id, name, kind, status, n, c}]}`을 `state.json`의 `crawler.issue_log`에 최대 72건·30KB까지 남깁니다. 크롤 없이 렌더링만 하는 빌드(`--no-crawl`)는 남기지 않습니다.

`trends.json`의 `issues` 블록은 `as_of, posts, communities, in_issues, low_data, badges, items[], hot[]`로 이루어집니다. 글은 배열 인덱스가 아닌 `posts[].rank`로 가리킵니다. 옛 `trends.rising`·`trends.top`·`trends.keywords`는 없앴고 `trends.categories`(카테고리별 글 수)만 남겼습니다.

## 로컬 실행

```bash
pip install -r requirements.txt
python build.py --base "" --out _site --force
python -m http.server -d _site 8000
# http://localhost:8000
```

- `--no-crawl` — 크롤 없이 운영 사이트의 `state.json`으로 렌더링만 합니다.
- `--state-file PATH` — 상태를 파일에서 읽습니다.
- `--now ISO` — 현재 시각을 주입합니다(테스트용). 크롤러의 TBS 조회 날짜, 커뮤니티 기대 시각(`missing`), 오전 보충, 알림 판정도 이 시각을 따릅니다.
- KST 12시 이후에 `--force`로 크롤하면 `data/daily/`에 오늘 리포트가 생길 수 있습니다. 테스트할 때는 `DAILY_DIR`을 임시 폴더로 지정하세요.
- 크롤하면 API 말고도 이슈링크(글이 적거나 멈춘 커뮤니티)와, 멈추거나 빠진 커뮤니티가 있으면 직접 스크래핑 요청이 나갑니다. 소스 점검만 할 때는 [소스 실측 프로브](#소스-실측-프로브-source-probe)를 씁니다.
- 로컬에서는 음성을 만들지 않습니다(`TTS_ENABLED` 미설정). `AUDIO_DIR`(기본 `.audio/`)에 지금 리포트와 맞는 `YYYY-MM-DD.mp3`·`.json`이 있으면 페이지에 싣습니다.
- 음성 MP3 인코더 `lameenc`는 선택 의존성이라 `requirements.txt`에 없습니다. 음성을 직접 만들어 볼 때만 `pip install lameenc==1.8.4`로 설치합니다. Actions는 별도 스텝에서 설치하고, 설치에 실패해도 사이트는 배포됩니다.

## 환경변수

로컬은 `.env`, Actions는 Secrets(키)와 Variables(나머지)에 넣습니다. 비워 두면 기본값을 씁니다.

| 변수 | 기본값 | 설명 |
|---|---|---|
| `GOOGLE_API_KEY` | (없음) | Gemini API 키. 없으면 AI 요약·데일리 리포트·음성만 꺼짐 |
| `GEMINI_MODEL` | `gemini-3.8-flash` | 기본 모델 |
| `GEMINI_FALLBACK_MODEL` | `gemini-3.6-flash,gemini-3.5-flash,gemini-3.5-flash-lite` | 예비 모델(쉼표로 여러 개, 순서대로 시도). `none`이면 끔 |
| `SITE_URL` | `https://gumoyaz.github.io/korean-community-crawler` | canonical·sitemap·llms.txt의 기준 주소. 경로 부분이 내부 링크의 base가 됨 |
| `GSC_VERIFICATION` | (없음) | 서치 콘솔 HTML 태그 인증값. 있으면 메타태그 출력 |
| `GA_MEASUREMENT_ID` | (없음) | GA4 측정 ID(`G-XXXXXXXXXX`, Variables). 있으면 모든 페이지에 gtag.js를 넣는다 |
| `STATE_URL` | `{SITE_URL}/data/state.json` | Actions 캐시가 없을 때 상태를 받아올 주소 |
| `MIN_INTERVAL_MIN` | `7` | 이 시간(분) 안에 다시 호출되면 크롤·배포를 건너뜀 |
| `DAILY_DIR` | `data/daily` | 데일리 리포트 저장 폴더 |
| `TTS_MODEL` | `gemini-3.8-flash-tts` | 데일리 음성 모델 |
| `TTS_FALLBACK_MODEL` | `gemini-3.8-flash-lite-tts` | 음성 예비 모델(1회). `none`이면 끔 |
| `TTS_VOICE` | `Kore` | 음성 목소리. 바꾸면 최근 7일 음성을 다시 만듦 |
| `AUDIO_DIR` | `.audio` | 음성 파일·메타 폴더 (Actions에서는 audio 브랜치 스냅숏) |
| `TTS_ENABLED` | (없음) | `true`일 때만 음성을 만든다. Actions가 직접 계산하므로 Variables에 넣지 않음 |

## 배포 설정 (최초 1회)

1. 리포를 **Public**으로 둡니다. 무료 플랜의 Pages와 Actions 무제한 사용 조건입니다.
2. Settings → Pages → Source를 **GitHub Actions**로 지정합니다.
3. Settings → Secrets and variables → Actions에서 Secret `GOOGLE_API_KEY`를 등록합니다.
4. Actions 탭 → **Build and deploy** → Run workflow로 첫 배포를 합니다. `main` 푸시로 돌면 크롤 없이 렌더링만 합니다.
5. [cron-job.org](https://cron-job.org)에 10분 간격 작업을 등록합니다. Actions의 `schedule`은 지연·누락이 잦아 백업으로만 둡니다.
   - URL: `POST https://api.github.com/repos/gumoyaz/korean-community-crawler/actions/workflows/pages.yml/dispatches`
   - 헤더: `Authorization: Bearer <fine-grained PAT>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`
   - 본문: `{"ref":"main"}` (성공하면 204)
   - PAT 권한: 이 리포만 선택, Repository permissions → **Actions: Read and write**
6. 음성 파일용 `audio` 브랜치는 음성을 처음 만든 실행이 자동으로 만듭니다. 따로 설정할 것은 없습니다(권한은 워크플로의 `contents: write`). 다만 브랜치 보호 규칙이나 rulesets를 모든 브랜치에 걸었다면 `audio` 브랜치의 강제 push(Actions 봇)를 허용해야 합니다. '강제 push 금지' 규칙은 브랜치를 처음 만드는 push는 막지 않고 두 번째 교체 push부터 막습니다. 그래서 첫 실행만 보고 판단하면 안 됩니다.
7. 수집 이상 알림(`source-health` 이슈)은 리포의 Issues가 켜져 있어야 합니다(기본값). 라벨은 워크플로가 처음 쓸 때 만들고, 권한은 `health` 잡의 `issues: write`라 따로 설정할 것은 없습니다.
8. 처음 배포한 뒤 **Source probe**를 한 번 수동 실행해 러너(해외 IP)에서 막히는 예비 경로를 확인합니다([소스 실측 프로브](#소스-실측-프로브-source-probe)).

## 산출물

| 경로 | 내용 |
|---|---|
| `/` | 메인 (JS가 `data/trends.json`을 읽어 렌더링) |
| `/data/trends.json` | 게시글(`prev_day`·`via`·`kept` 포함), 지금 뜨는 이슈(`issues`), 수집 상태(`status`·`source_health`), 카테고리별 글 수, AI 요약, 갱신 시각 |
| `/data/state.json` | 다음 실행이 이어받을 상태 (점수 이력, 직전 글 목록, AI 요약, 이슈 튜닝 로그, 커뮤니티별 상태, 전날 상위 글, 이슈링크 캐시, 알림 연속 횟수) |
| `/daily/`, `/daily/YYYY-MM-DD/` | 데일리 목록·상세 (서버 렌더링) |
| `/audio/YYYY-MM-DD.mp3` | 데일리 음성 (지금 리포트 내용과 맞는 것만, 최근 14일) |
| `/sitemap.xml`, `/robots.txt`, `/llms.txt`, `/404.html` | SEO·AI 크롤러용 |

## SEO / AI 검색

- 페이지마다 description, canonical(끝 슬래시 통일), Open Graph, Twitter Card, JSON-LD(`WebSite` / `Article` / `CollectionPage`)를 넣습니다.
- `sitemap.xml`에는 메인·데일리 목록·날짜별 리포트가 들어갑니다. `lastmod`는 리포트 생성일입니다.
- `llms.txt`는 ChatGPT·Claude·Gemini·Perplexity 같은 AI 크롤러용 사이트 안내서입니다.
- 프로젝트 페이지(`/korean-community-crawler/`)라서 `robots.txt`는 크롤러가 읽지 않습니다. 서치 콘솔에 `sitemap.xml`을 직접 제출해야 합니다.
